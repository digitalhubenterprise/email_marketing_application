## 2. Audited Security Controls & Patches Ledger

### A. CSV Upload Memory Exhaustion (OOM) Protection
- **Status**: **RESOLVED & VERIFIED**
- **Affected File**: [`backend/app/api/contacts.py`](file:///e:/Work/Development_Projects/email_marketing_application/backend/app/api/contacts.py#L224-L357)
- **Vulnerability**: Standard CSV upload endpoint read the incoming files into memory (`file.read()`) all at once before validating size. A malicious user could crash the backend by uploading a huge file, causing memory exhaustion (OOM).
- **Remediation**: Implemented a streaming reader inside the router endpoint that pulls files in **1MB chunks**. The total byte size is verified inside the streaming loop. If the cumulative file size exceeds the `CSV_MAX_SIZE_BYTES` limit (5MB), the read process terminates immediately, throwing an **HTTP 413 (Payload Too Large)** exception before the entire payload is buffered into memory.

### C. Cross-Site Scripting (XSS) Prevention
- **Status**: **SECURE & VERIFIED**
- **Affected File**: [`frontend/src/pages/Templates.tsx`](file:///e:/Work/Development_Projects/email_marketing_application/frontend/src/pages/Templates.tsx)

- **Implementation**: Integrated client-side `DOMPurify.sanitize(...)` to sanitize and strip malicious scripts, event handlers, or payload injections from custom user HTML marketing layouts before they are loaded into the browser Document Object Model (DOM).

### D. Insecure Direct Object Reference (IDOR) Unsubscribe Guard
- **Status**: **SECURE**
- **Affected File**: [`backend/app/api/tracker.py`](file:///e:/Work/Development_Projects/email_marketing_application/backend/app/api/tracker.py)
- **Control**: Prevented attackers from opt-ing out or unsubscribing random subscribers by enumerating sequential database primary keys.
- **Implementation**: Unsubscribe requests require an HMAC-SHA256 signature token generated from the contact's ID and signed by the server's private `JWT_SECRET`.
- **Side-Channel Protection**: Signatures are verified using python's `hmac.compare_digest` to mitigate side-channel timing analysis attacks.

---

### E. SQL Injection Prevention
- **Status**: **SECURE**
- **Control**: Eliminated all potential raw query SQL injection vectors.
- **Implementation**: The application database layer exclusively utilizes **SQLAlchemy ORM 2.0** objects and select constructs for transactional mappings. There are no raw string interpolations (`%s`, `f"{var}"`) inside queries, ensuring all user inputs are correctly escaped and parameterized by the database engine.

---

### F. CORS & Secure HTTP Headers
- **Status**: **SECURE**
- **Affected File**: [`backend/app/main.py`](file:///e:/Work/Development_Projects/email_marketing_application/backend/app/main.py)
- **Controls**:
  - **CORS Allowlist**: When `ENVIRONMENT=production`, all local references (`localhost`, `127.0.0.1`) are filtered out from allowed origins.
  - **Security Middlewares**: Injects robust HTTP headers:
    - `X-Content-Type-Options: nosniff` (Prevents MIME sniffing)
    - `X-Frame-Options: DENY` (Mitigates clickjacking)
    - `X-XSS-Protection: 1; mode=block` (Blocks browser reflection XSS)
    - `Strict-Transport-Security` (Forces TLS/HTTPS connections)
  - **Server Signature Masking**: Safely deletes the default `server` signature from HTTP responses to prevent tech-stack finger-printing.
